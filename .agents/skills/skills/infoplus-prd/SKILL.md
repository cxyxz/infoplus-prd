定位工具根目录 `INFOPLUS_PRD_HOME`，未设置时在当前项目查找 `package.json` 中的 `infoplus-prd`。读 README 的配置说明。只处理用户指定的流程，不读取 Chrome 凭据或导出敏感请求信息。

## 执行入口与知识库

适用场景：按流程编号或名称，采集已授权的 InfoPlus IDE 版本，重建 Workflow、表单、字段选项、Debug 办理证据和唯一业务需求 Word。输入方式是 `流程编号` 或带编号标题，例如 `Z1775`、`Z1775：流程名称`；显式对比目录使用 CLI 的 `--output-dir`。

执行实际采集或 Debug 前，必须先读 [执行决策手册](references/debug-playbook.md)，再按症状读取 [问题索引](references/issue-index.md) 命中的知识条目。遇到未知问题时先匹配关键词，再查代码和现有测试；优先采用标为“已真实验证”的方案。只允许有限次可恢复重试，不因单个未知问题大规模改写 Skill。能力状态分为已真实验证、仅自动化测试、部分实现和待实现，详见 [能力状态](references/capability-matrix.md)。

常规顺序：定位版本 → 读同版本缓存 → 采集静态 Workflow/XSN/Views/字段 → 核对专用 Chrome 与 Debug 模式 → 优先后台 Debug、不可用时前台回退 → 逐节点取证 → 复用缓存生成唯一 Word → 核验成果与证据。不要把生成 Word 当作采集完成。

1. 按编号、名称和版本定位 `output/<编号>/`。分析已有采集资料时运行 `node src/cli.mjs collect-online <流程编号目录>`，再执行 `node src/cli.mjs generate <流程编号目录>`。在线采集先核对同版本的 Debug 入口和隔离边界，随后按报告继续前台采集。在线命令退出 2 或 Chrome 不可用时，继续使用已有证据生成文档。仅重生成 Word 时直接执行 `generate`。本地资料缺失时按第 2 步采集。`run` 是含缓存和 Debug 调度的默认入口；`generate` 只消费已有缓存，不重新采集。
2. 缺失或需更新时，使用获授权的 Chrome 会话执行 `node src/cli.mjs scan <编号或名称> [输出根目录]`。未配置 `INFOPLUS_IDE_URL` 时，使用当前会话已核实的 IDE 入口或该站点的已授权项目缓存入口。多个版本时按可用版本和已核对的目标指定 `INFOPLUS_VERSION`。Chrome 扩展采集可在 IDE 的 Views 表按实际 XSN 链接下载，单个标签只能同时进行一次下载。按阶段名称或视图 ID 匹配实际文件。
3. 实测的 InfoPlus 格式自动解析。工作流响应的 `entities[0].guiDefinition` 为 XML，`released` 是该定义的发布标志。字段响应包含主模板及 `templateViews`。Views 响应的 HTML 只提取阶段索引和同源下载路径，IDE 字段表提取控件类型和必填标记。手工 `workflow-map.json` 用于兼容其他已核实的 JSON 格式。
4. `options`、`scan` 和项目内的 Chrome DevTools MCP 复用通过 `start-infoplus-chrome.ps1` 启动并已登录的专用 Chrome，连接 `http://127.0.0.1:9222`。连接成功不等于页面可操作：还要确认专用资料目录、目标标签、同源页面、iframe 内真实表单、当前步骤和写入权限。超时、iframe、页面重载、标签切换和会话失效分别按 [Chrome CDP 与页面读取](references/troubleshooting.md#chrome-cdp-与页面读取) 处理。不反复重启浏览器、重新登录或创建流程实例。启动和关闭方式见 README。
5. 选项以实际值、显示名称、来源、阶段和触发条件保存。一次 `suggest` 响应、单次条件组合或不同版本的页面都不能视为完整字典。来源不同或条件不同的结果分别保留。已取得的脱敏 HAR 可通过 `node src/cli.mjs import-options <流程编号目录> <HAR>` 补充。已核对的业务方说明可存入匹配版本和定义 ID 的 `field-options-reviewed.json`，实际值未知时留空。
6. 在用户已授权的 InfoPlus 旧平台范围内，优先使用目标版本的非发布 Debug。只有 IDE 版本行 Debug 入口、Instances → DEBUG 记录、页面调试标记、实例归属和当前办理身份同时吻合，才标为 Debug 实测；普通委托页、前台申请或 URL 中的 `release=false` 不足以证明。共享回调和普通通知本身不阻断已授权常规 Debug；仅对未授权、不可逆外部系统写入停止该动作。禁止修改正式定义、部署、删除业务记录或绕过权限。只读前台采集仍拦截发起、保存和提交。
7. 唯一业务 Word 共用同一份标准化结果及已核对的业务规则。需要补充规则解读时，按证据核对一次并写入 `reviewed-rules.json`。成功时使用返回的 `documents` 路径和 `fieldOptions` 摘要。结构检查通过与选项覆盖完整分别报告。退出 2 表示部分输出，按需查看 `analysis-report.json` 和有关证据。
8. 默认只交付 `流程编号：流程名称需求文档.docx`。Markdown、CSV、JSON、XSN 和流程图作为内部资料保留，按需读取。`requirements_custom.docx` 是旧命名，确认已有当前版替代且旧件无独有内容后才清理。用 `node src/cli.mjs generate-custom <流程编号目录> [模板 JSON]` 可单独重生成业务版。默认模板在 `config/requirements-custom.json`。流程专用说明可放入 `config/business-profiles/<编号>.json`，须匹配采集版本及定义 ID。
9. 业务版附录 A 优先复用核对过的 `workflow-original.svg`、`workflow-original.png` 和来源记录。无缓存时，`scan` 会从已登录 Chrome 的 Workflow 编辑器采集画布。使用 Chrome 扩展连接时，可在对应版本的 Workflow 页读取 `iframe[src*="/editor-vue/"]` 中包含标签的完整 SVG，保留画布全部元素并保存到 `raw/workflow-editor-dom.svg`。SVG 超过浏览器工具返回上限时，分段读取并确认结束标签。运行 `node src/cli.mjs workflow-original <流程编号目录> [IDE 画布 SVG]` 进行核对和转换，再生成业务版。只有可核对的原图才插入附录。若 IDE 无法打开或未暴露完整 SVG，请说明限制，并请用户提供从对应 Workflow 编辑器导出的完整 SVG。
10. 欢迎页、办理须知和其他无字段阶段也纳入阶段清单。用入口视图、节点绑定和已核对的办理路径确定用途及顺序。阶段图优先使用同版本的前台完整截图，其次使用 XSN 静态预览并注明来源。前台补采默认仅重放已缓存的预览页面，允许受控预览读取。仅在已核实具体入口的 GET 只加载预览时，才可用 `stages <流程编号目录> <已核实的前台入口 URL>` 刷新该页。拦截开始办理、保存、提交等动作。缺少可操作字段不代表页面采集失败。
11. 从 IDE 目标版本行的 Debug 功能核对启动入口。进入表单后用页面的「调试模式」标记、步骤实例和定义 ID、业务流水号对应的 `Instances → DEBUG` 行及实际指定办理人交叉验证。普通委托提示、`release=false` 或 `entrust=true` 仅用于辅助定位。经核实的 IDE Debug 链接可能打开委托中转页，自动启动只可继续当前登录身份，直到实例与平台标记均核实后才可办理。身份按当前节点实际办理角色选择并在切换后重新核对节点、身份和可操作按钮；权限不足时重新核对角色，不绕过权限。技术不可用时回退前台，保留核验失败证据。
12. `normalized/bundle.json` 中 `nodeEvidence` 按节点关联 IDE、XSN 和版本核对过的前台视图观测。共享视图的字段选项和联动只验证视图，不能证明某审批人实际操作过该节点。按 `analysis-report.json` 的 `runtimeCoverage` 报告实测身份、节点和路径。仅对实际走过的操作标记为已验证。

13. 已登记的实例使用 `debug-session <流程编号目录> <实例ID> verify` 只读核验，`observe` 同时采集当前步骤。`next <待办步骤号> <流程编号>@<版本>` 使用同一实例的实际待办链接；身份切换只使用明确的 Debug 窗口，随后重新核对。`act <动作名> <授权范围>` 和 `confirm` 在发送前重查第 11 条的证据及页面 executable 权限、步骤状态与动作；证据不齐时停止该操作。普通确认可自动处理。

14. `raw/debug-runs.json` 按实例保存字段、成员范围配置、动作、确认和后续待办。成员候选分页不代表完整范围；没有过滤配置不代表全校可选。`raw/manual-debug-reference.json` 单独保存用户截图观察和旧系统问题，不计入自动验证。业务文档和内部资料复用这些标准化证据。已完成节点不重复提交；非零业务错误码即使 HTTP 200 也不算办理成功。
15. 结果下载仍是流程阶段。须按真实按钮取得申请表和批件，并核实最终实例状态；“批件制作中”、空待办或成功进入结果页均不能当作流程结束。区分实例正式完成、主要审批完成、等待业务材料、外部服务阻断、表单校验阻断和当前分支未验证。优先完成一条代表性正常路径，再用独立实例补充重要分支；互斥按钮不在同一实例连续尝试。未执行分支仅保留 Workflow 映射并标注未实测，连线数量不等于完整业务路径数。
16. 每次阶段采集后使用 stage-field-differences 分析同一实例实际跳转两端的字段状态，区分缺少绑定、显隐、只读及必填变化。不得将节点观测差异直接归因为角色或业务条件；未观测节点不参与专属字段结论。普通字段保持原三列表格，关键审批和人员字段在可配置的四列特殊字段表中说明来源、范围、阶段和填写规则，并引用真实截图。局部截图存于 debug-evidence，缺少截图或因果证据时明确保留待验证状态。
17. 已完成节点需要补图时，可运行 `node scripts/capture-debug-history.mjs <流程编号目录> <已登记实例ID>`，仅使用当前实例实际历史链接读取 snapshot 页面。历史局部图存入 debug-evidence，证据存入 raw/debug-history-evidence.json；生成时纳入业务版附录 C，不能增加已验证节点或条件分支计数。成员服务的 settings 仅保存白名单过滤配置，不保存身份值或凭据；userTraversal 的搜索/分页行为不等于跨单位权限。人员目录来源、候选过滤和跨组织实测结论分别记录。未知范围不得写成任意选择。所有字段清单强制采用「分组 + 单字段独立记录」六列表格，禁止多个字段共享同一个字段名称单元格；字段身份以真实 ID 为准，分组只用于分类。遇到批件制作中保留外部依赖待核实状态，不自动循环重试。文档锁定时在同一流程编号目录保存 .pending 文件，报告正式文件未更新；命令有限重试，解锁后重新运行 generate 安全替换。禁止用新验收目录代替正式交付。

18. 常规分析默认 output/<编号>/。用户显式指定 --output-dir 时，该目录是本次独立正式成果目录（例如 Z1775workbuddy）；不写回或覆盖编号目录。缓存、截图、Word 和验收报告归属同一输出根目录；对比时只读访问原版，不自动移动成果。_verification 仅作临时测试。Word 先写同目录 `.pending`，校验 ZIP 和 document.xml 后尝试原子替换；被占用时保留原文件与临时文件，提示解除占用后重跑 `generate`，不重新分析业务数据，不先删原文件。

19. 每次本地分析生成 reports/path-coverage.json，按非自循环、非隐藏 Workflow 连线建立有限验证项，保留条件表达式、实际按钮、后续办理前沿和证据来源。该数量不等于完整起终点业务路径数量。按实例区分正式结束、收尾待验证、业务条件阻断、技术故障及进行中；HTTP 成功但业务码非零不是办理成功。终点邻接只证明剩余拓扑，不自动证明之前全部条件。新的授权 Debug 实例应先登记 path-plan 事件，关联目标连线，复用已有未完成实例，不批量启动。当前支持覆盖分析及既有实例操作。显式授权启动入口已接入；V1.2 起通用自动填表与逐节点调度已实现，见第 23-31 条。

20. 默认执行 `node src/cli.mjs run <编号、名称或带编号标题>`，缓存优先并按统一配置优先尝试非发布 Debug；`--static`、`--offline`、`coverage <编号>` 和 `issues` 对应静态、离线、覆盖查询及问题查询。优先恢复已登记实例，受策略上限约束选择代表性未覆盖路径；不能安全确定测试值、动作或真实外部影响时记录阻断，不宣称已验证。记录新问题于 docs/known-issues.md，通用改进列入 docs/improvement-backlog.md。具体自动化能力以运行报告和 README 为准。

21. 用 `linked-fields` 筛查前置业务字段，再依据页面说明、配置或脚本核实前置流程。优先复用流程专属字符串输入；缺少值时按版本匹配的 `config/workflow-inputs/<编号>-linked.json` 调用办事中心只读历史查询，或使用 `linked-dashboard`、`linked-discover` 按授权范围查找。核对前置流程、状态、详情业务字段、申请工号和当前模拟身份。多个候选时补充条件。流水号用于定位实例，业务编号来自详情字段，两者不得混用。用 `input-set` 保存来源和验证状态；自动查找失败时可询问一次，获得后持久化。需求文档只写脱敏规则、来源和带出关系，具体流程编号、工号和人员仅作案例证据，不硬编码到通用逻辑。详见 [跨流程关联与身份匹配](references/cross-flow-identity.md)。
22. 用户已手动推进的步骤用 `debug-session ... adopt <编号>@<版本>` 核实并登记，之前动作按人工验证处理。将已核实的上游流程、字段绑定、带出状态和表单权限写入 `raw/cross-flow-evidence.json`，供唯一业务 Word 共用。

### V1.2 · Debug 全流程深度采集（2026-11-16）

23. 进入每个可编辑节点必须先做**全页面必填扫描**（`src/form-autofill.mjs`）：覆盖可见区、滚动区外、条件隐藏、单选/复选/下拉/日期区间/文本/成员/组织/附件/子表格，以及联动后新增字段。InfoPlus 的 `entity.fields` 不一定带 required 标记，必填由控件 `validate[...]` 类与 `.formError` 驱动，禁止只依据 entity.fields 判定。红字提示在补填后不会即时清除，必须按控件真实值 / radio checked / 附件上传状态判定是否已满足。
24. **普通必填校验失败禁止终止 Debug 分析**。用 `scripts/v12-repair-and-submit.mjs` 执行「关闭提示 → 定位未满足字段 → 填合规测试值 → 再校验 → 重新提交」循环；提交可暴露新的动态必填项，须自动补填后再提交。扫描必须覆盖滚动区外、条件隐藏、单选/复选/下拉/日期/成员/组织/附件/子表格和联动新增字段，不能只看当前屏幕，不能按模板必填属性断言运行时规则。测试值按字段语义推断；附件只用明确标记的 DEBUG 占位文件；不得伪造法律效力材料或绕过权限。错误指纹连续两次相同才保存证据并转针对性排查，不得无限点击。关闭提示只表示已读，不等于校验成功。
24a. 弹窗统一分为普通说明、提交确认、必填校验、格式校验、业务条件校验、外部服务异常和未知。普通说明可关闭；提交确认须经 Debug 授权和页面权限核验。校验先保存证据再关闭，定位并修复字段，重新扫描后才可重试；关闭提示不表示校验成功。业务条件与服务异常分别记录。未知提交结果先核验当前实例和待办，禁止盲目重复提交。未知、删除、部署等弹窗保留。
25. **节点按钮完整发现**必须同时读取 `entity.actions` 与 DOM 命令栏 `a[name^="infoplus_action_"]`。平台级按钮（如 kill/终止）不在 entity.actions 中，不得遗漏。逐按钮记录名称、所在节点、权限、前置条件、必填要求、对应 Workflow 连线、预期与实际目标节点、是否需切换身份。
26. 用 `src/node-button-map.mjs` + `scripts/v12-build-button-map.mjs` 建立「按钮 → Workflow 连线(ID) → 目标节点」映射，含自动网关分支。必须滚动到节点底部读取命令栏。同名不同动作、条件或目标保留为独立操作；同一动作的隐藏/可见副本按动作 ID 合并。HTTP 200 不等于审批成功；HTTP 成功、业务码和真实后续待办共同确认流转。未知条件写“具体执行条件待验证”，不得使用空泛套话。未点击的按钮不得从文档遗漏。
27. 逐节点执行循环固化于 `scripts/v12-walk-flow.mjs`：进入节点 → 识别身份 → 采集全部字段 → 采集全部按钮 → 分析业务条件 → 填测试数据 → 处理校验 → 提交 → 核对真实待办与流转 → 保存证据 → 切换身份 → 下一节点。每步真实流转后立即写 `flow-progress.json`（visited/trace/transition/blocked）；中断后从当前实例节点恢复，不从头开始。
28. 多路径策略：优先完成一条正常办理路径（正向动作：提交/审核通过/提交并打印/报销已完成），再验证影响审批顺序的重要分支；退回、终止、特殊转办等负向动作默认不在同一实例连续尝试，必要时启动独立 DEBUG 实例。正向/负向语义使用通用正则，不针对具体流程硬编码。
29. 稳定性：Debug 导航超时 `INFOPLUS_NAV_TIMEOUT`（默认 30000ms）、动作等待 `INFOPLUS_ACTION_WAIT_TIMEOUT`（默认 95000ms，循环场景 20000ms）、CLI 完整堆栈 `INFOPLUS_DEBUG_STACK`。提交前释放 CDP 连接避免与 Skill CLI 并发争用。必须区分 CLI 技术失败与业务校验失败：前者有限重试并记录，不计入「校验已处理」。
30. **生成文档前必须输出「节点采集完成度检查表」**并逐项核对：Workflow 节点全部识别；每节点字段实测优先、无法进入用 XSN 补充；节点专属字段标明显示/编辑/必填规则；每节点全部按钮从配置或页面识别；按钮到目标节点已建映射；代表性正常路径尽可能走到结束；特殊路径优先验证影响审批规则的分支；截图各节点与特殊规则均有来源说明。未通过不得宣称完成。
31. **完成条件重新定义**：仅生成唯一业务 Word 不代表完成。至少核查：节点识别完整、视图与字段提取、按钮全量、按钮-分支映射、代表性路径实测、未实测路径记录、常规校验失败已处理、真实 Debug 证据、实际验证与静态推断分离、全部规则写入文档。因外部服务或权限无法进入的节点，保留静态配置分析与缺失证据清单，不冒充实际验证。

### V1.2 · 截图取证与图文一体化（2026-11-16）

32. **截图与字段、按钮同为一级证据**。每个实际进入的办理节点默认采集三类图：整页结构图、底部业务操作按钮图、特殊字段/条件/校验图。优先采集真实 Debug 页面中 iframe 内唯一 `#form_holder` 的完整内容，展开内部滚动区并检查横向内容；长图按业务模块裁剪，不按视口机械分成 1/3。保留高清原图，文档图脱敏；历史只读、XSN 静态预览、校验提示和工具错误分别标注。无业务价值的重复、遮挡、空白或错误图不进入 Word。历史快照必须拦截 `doAction/start/save`，且不能增加新的已验证动作。
33. 截图按节点归档到 `debug-evidence/NN-节点名-ID/`，并生成 `screenshot-index.json` / `.md` 与 `screenshot-quality.json`。索引必须关联流程编号、实例 ID、节点、身份、页面类型、截图类别、字段/按钮、触发条件、来源和验证状态。质量门禁检查文件存在、PNG 可打开、尺寸、重复、节点匹配；重复图不得入库，平台工具栏不得冒充业务按钮。
34. 文档展示图与原始证据分离：`full-page.png`、`*-segment-*.png`、`action-buttons.png`、特殊字段局部图用于脱敏展示；未脱敏原图只保存在节点 `original/` 子目录，不直接插入 Word。长页面按分段插入，关键字段和按钮可用局部图，禁止把长图压缩到无法阅读。
35. **业务版正文采用图文一体化**：重要节点按「业务说明 → 字段表格 → 真实页面截图 → 按钮流转表 → 特殊规则」组织，截图紧邻其解释的规则；同一图片不得在正文和附录重复堆叠。完整字段与技术分析保留在内部 Markdown、JSON 和证据报告中。
36. 不能采集的截图必须记录原因和替代证据。若历史快照不暴露业务按钮，可从同一实例的实时完整截图裁剪底部按钮区并注明来源；若完全没有实时按钮证据，则删除退化截图并明确标注「配置确认、未实际截图」，不得用平台工具栏或 XSN 预览替代。身份限制、模拟登录候选不可用等页面证据应单独截图并记录。
37. 独立对比使用 `node src/cli.mjs run <编号> --output-dir output/<对比目录>`；重生成使用 `node src/cli.mjs generate <对比目录>`。证据、截图索引、报告和 Word 均留在此目录。截图引用限定在当前目录并使用相对路径，不跨版本借用绝对路径。保留原目录不变，不在结束时自动移动对比成果。

### V1.2.1 · 真实页面截图与文档质量修复（2026-11-17）

38. 进入 Debug 节点后优先采集唯一 `#form_holder` 的完整业务表单：宽屏视口、展开内部滚动容器、隐藏平台导航并脱敏字段值；测量内容宽高后保存 `full-page.png`。禁止用固定浏览器视口的 `page-segment 1/3` 冒充完整页面；超出一次可靠采集尺寸时记录缺失，不伪造拼接。
39. 图片进入 Word 前按 A/B/C/D/E 分类：A 完整业务页面、B 业务模块或按钮局部、C 有明确规则的业务校验、D 调试工具错误、E 重复遮挡空白无效。只有 A/B/C 可进入需求文档；D 保留内部诊断，E 标记废弃。索引必须记录节点、实例、来源、验证状态、原图关系与裁剪坐标。
40. 长表单采用两层展示：节点保留完整原图，正文引用按业务模块边界裁剪的局部图，并在按钮表附近放置真实底部按钮图。图题使用业务模块和证据等级，不再使用滚动位置编号。没有实时按钮证据时删除退化截图并标注「配置确认、未实际截图」。
41. 业务版章节按业务概述、前置关联、完整流程、审批规则、字段清单、节点图文、退回重提、待确认、附录排列。历史阻断只在后续Debug未解决时保留为当前问题；已解决的历史问题保留在证据中，不继续作为当前阻断。图片不得在同一文档重复堆叠，章节不得倒序。
42. 附录 B 的超长 XSN 预览不得压缩成单页窄图。生成器按 Word 可用页面高度连续裁切同一 PNG，并在后续页标注「续 N/M」；“同一实例实时完整截图底部裁剪且已匹配业务按钮标签”的按钮图属于 B 级。内部资料仍保留原有阶段图。

### V1.3 · 单文档交付与业务需求质量

43. 默认 `run/generate/scan` 只输出命名业务 Word；`generate-custom` 保留兼容。`requirements.md`、CSV、JSON 等保留内部分析。旧详细 Word 仅在唯一文档生成和验收通过后清理；禁止批量清理其他流程。正文只呈现业务规则、字段、真实页面和待确认项，不堆接口 JSON、节点 ID 或脚本源码。
44. 固定自动编号：业务概述、前置业务与数据关联、完整业务流程、流程节点与办理角色、表单字段清单、核心办理节点图文说明、业务分支与流转规则、待确认事项、附录。正文和附录使用原始 Workflow 图。
45. 节点按正常 Workflow 拓扑排序，退回循环单独说明；同层并行节点注明并行关系。字段表优先新增、可编辑、必填及状态变化，不重复通用只读信息。成员、部门、附件和日期按业务组件识别。
46. 生成前用 `scripts/v12-build-button-map.mjs --workflow <目录>/workflow.mmd --evidence <目录>/<已有节点证据目录> --output <目录>` 更新按钮映射。原始动作 ID 保留，同动作的隐藏/可见副本合并；同名不同动作不合并。只有提交记录及真实后续待办能证明实际执行。未知条件写具体执行条件待验证。
47. 页面来源分为实际办理、历史只读、Workflow、XSN、未验证或阻断。历史截图不证明当前编辑权限。所有正式成果服从显式目录；原对比基线保持只读。

### V1.3.1 · 字段原子化与分组结构修复（2026-11-17）

48. 字段原子化是强制规则：一个真实业务字段占一行，字段身份优先取真实 field ID；同一 ID 跨阶段出现时可汇总为一条记录并保留每阶段必填、只读、显隐与来源差异。分组、类型、阶段、数据来源相同都不能合并不同 ID；同名字段若 ID 不同，未核实前分别保留。禁止按顿号、逗号、冒号或换行拆分已有显示文本来反推字段边界。缺少可信字段身份时记录待解析项，不生成猜测字段。
49. 所有字段型表格统一六列：分组、字段名称、字段类型、必填、出现阶段、数据来源/规则。全局字段清单、前置关联字段表、节点字段表均遵守；业务规则表、节点列表和按钮表不属于字段清单。Word 渲染不得为了压缩表格把多个字段名拼入同一单元格；允许表格跨页，并以实际 DOCX 表格行数核对。

## 知识库维护

执行结果回写遵循：匹配已有问题 → 采用已验证方案 → 保存本次证据 → 成功则补充适用条件 → 失败则记录新原因 → 只有确认通用规律才更新知识库。流程专属规则只进入对应版本的证据或 `config/business-profiles/<编号>.json`，不得写进通用策略。每条方案必须保留验证状态，未验证方案不得表述为可靠能力。
