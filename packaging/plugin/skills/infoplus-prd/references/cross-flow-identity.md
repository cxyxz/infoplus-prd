# 跨流程关联与身份匹配

## 识别前置依赖

先用 `linked-fields` 找候选字段，再依据欢迎页说明、脚本、Workflow 动作和配置确认前置流程。仅凭相似字段名不得认定关联。`config/workflow-inputs/<编号>-linked.json` 只保存版本、字段、来源、验证状态和脱敏规则；人员、工号、实例号只见受控证据。

## 获取真实业务编号

流水号用于定位实例；业务编号（例如团组编号）来自前置详情字段，两者不得混用。按版本匹配的前置流程定义、已完成状态、详情业务字段和申请工号精确核对。多个候选时补充条件，不能任选。自动查询失败时可向用户询问一次，获得后持久化，避免重复询问。

Z1775 曾因虚拟团组编号收到 `22001：团组编号不存在`；后续通过 Z0095 已完成申请取得真实团组编号并匹配申请人才继续。该流程关系只作为案例，不写入通用判断逻辑。

## 验证关联与带出

在当前 DEBUG 实例填入匹配的业务编号 → 读取业务响应 → 核对真实下一节点 → 逐字段比对带出值、只读/可编辑状态和来源。静态模板显示值不自动证明运行时默认值；历史只读页面不证明当前权限。原申请修改或状态变化后的重新同步规则未验证时保留待确认。

## 成员选择与组织范围

记录四类信息：人员目录来源、组织/部门/党委等过滤配置、上一节点指定或自动带出、当前申请人/办理人关系。成员候选只有一页或只有搜索结果，不等于完整可选范围；`userTraversal` 的分页行为不等于跨单位权限。没有过滤配置也不能写成全校可选。无法确认时保存 settings、候选截图、字段绑定和节点上下文，结论标“范围待确认”。

## 身份切换

按节点实际办理角色选择 Debug 身份，切换后重新读取当前节点、办理人、actions 和权限；不要只看页面地址或 Continue to debug 的结果。权限不足时核对角色并重新选择，不绕过权限。上一个模型手动办理的步骤用 `adopt` 登记为人工验证，不合并进自动操作记录。
