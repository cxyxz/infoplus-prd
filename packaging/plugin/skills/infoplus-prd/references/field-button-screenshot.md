# 字段、按钮与截图经验

## 字段类型与证据优先级

证据强度顺序：当前 Debug 页面实际交互 > 同实例真实待办和字段写入结果 > XSN/Workflow 配置 > 历史只读页面 > 未验证推断。附件、成员、组织、日期和选项字段按业务组件识别，不能因底层 API 是 string 就写“单行文本”。

模板必填只说明静态配置；运行时必填由 DOM `validate[...]`、`.formError`、实际值和提交响应判断。条件字段记录触发条件、显隐、只读、必填和可编辑变化；历史只读快照只证明当时页面内容。相同类型且规则完全相同的普通字段可合并，节点专属差异保留。

## 按钮与分支映射

完整按钮来源是 `entity.actions` 加 DOM 命令栏 `a[name^="infoplus_action_"]`。平台级 kill/终止按钮也可能不在实体动作中，需要滚动到页面底部采集。保留按钮名称、动作 ID、所在节点、前置条件、Workflow 连线、目标节点、是否点击、真实流转结果。

同一动作的隐藏/可见副本按动作 ID 合并；同名但动作 ID、条件或目标不同的按钮必须保留为多个操作。实际验证要求真实点击加业务响应、后续待办或节点变化；只有 HTTP 200 时标“提交成功、后续待核对”。“满足当前节点执行条件”不是需求描述，条件未知写“具体执行条件待验证”。

## 截图质量

优先采集真实 Debug 页面中 iframe 内唯一 `#form_holder`：宽屏视口、展开内部滚动容器、隐藏平台导航、脱敏字段值、测量完整宽高并保存高清原图。横向内容不能裁切；长图按业务模块裁剪，不按视口机械分成 1/3。底部按钮图必须包含业务按钮和标签，平台工具栏不算。

图片分类：A 完整业务页面；B 业务模块或真实按钮局部；C 有明确规则的校验；D 调试/工具错误；E 重复、遮挡、空白或无效。只有 A/B/C 进入正式 Word，原图留在 `original/`。每张图关联流程、实例、节点、身份、来源、验证状态、裁剪坐标和解释的业务规则。条件切换前后和成员候选变化应成对采集；无法获取时记录缺失，不用静态 XSN 或错误图冒充。
