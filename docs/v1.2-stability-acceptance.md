## 修复行为

1. 弹窗统一区分普通说明、提交确认、必填校验、格式校验、业务条件校验、外部服务异常与未知。含“确定”按钮不足以成为办理确认；危险操作优先拒绝。
2. 校验文本先记录，再关闭提示。字段补填后重新扫描，普通非空值不能证明电话等格式正确。多弹窗关闭按逆序处理，避免 DOM 列表变动导致定位超时。
3. 修复脚本填值前核对目标实例、版本、IDE DEBUG 和可执行权限。无法定位字段时保存问题，不重复空提交；可定位的字段有限修复，未知格式保留待核实。移除根据“已完成”提示自动勾选业务声明的行为，仅提供候选定位。
4. 缺少业务返回码不算成功。提交结果未知或服务异常时读取页面状态并执行只读实例核验，保存证据，禁止盲目重试。errno=0 是动作接受，不等于整个流程结束。
5. 断点绑定实例，旧检查点需与实际待办匹配；恢复保留既有观测。当前步骤完成、缺少页面或名称包含“完成”，均不能证明实例到达最终结束。
6. 按钮精确匹配 Workflow 名称；没有实例和实际目标的记录不标为实测。修复无连线 ID 的 Mermaid 解析。
7. 显式目录参数原地处理；新增 `--output-dir`，覆盖 run/scan 及主要目录命令，拒绝不支持的组合。旧隔离环境变量兼容。跨目录复制 Word 的旧脚本要求改用同目录生成。
